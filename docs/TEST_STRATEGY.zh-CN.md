# Sync Tunnel 测试策略

## 1. 质量目标

测试首先证明“不会静默丢失原始字节”，其次证明最终收敛、可恢复、性能可接受。仅验证 HTTP 返回成功不足以证明同步系统正确。

## 2. 测试层次

### Go 单元测试

- 路径、ID、哈希和配置验证；
- 新建、修改、删除、重试和 revision 冲突；
- 快照稳定分页、游标过期和 Vault 隔离；
- migration、设备水位线、历史恢复和 GC 资格；
- 配额、速率限制、磁盘错误和内容损坏。

### 插件单元测试

- glob、路径规范化、冲突命名和同步配置 fingerprint；
- 扫描缓存和事件合并；
- 首次同步计划；
- outbox/inbox 状态转换；
- 同步摘要、错误分类和重试策略。

### 模型状态机测试

使用内存 Fake DataAdapter 和测试服务器创建 2 至 5 个客户端，随机执行：

- 新建、修改、删除和重命名；
- 同一路径并发修改；
- 客户端离线和恢复；
- 请求在提交前或提交后断开；
- 客户端索引丢失；
- 排除规则变化；
- 设备 retired 后重新接入。

最终断言：在线同步结束后所有未冲突路径收敛；每个冲突的原始内容至少存在一份；服务端和客户端索引指向的哈希与实际字节一致。

### API 与端到端测试

- 未授权、权限不足和设备撤销；
- 全文件与分块上传下载；
- 幂等 operation ID；
- 快照后并发变更；
- Docker 重建后数据保留；
- 备份、校验、恢复到新目录并重新同步客户端；
- Cloudflare Access 场景使用独立人工验收，不在公共 CI 保存真实凭据。

## 3. 故障注入

- 文件扫描或上传期间再次修改；
- 下载写入一半时进程终止；
- 服务端事务提交后响应丢失；
- SQLite busy、损坏和磁盘写满；
- `/data/blobs` 缺失、被篡改或权限错误；
- 长期离线设备跨过 tombstone 保留期；
- 服务器升级和数据库 migration 中断；
- 系统时间明显错误；
- 大小写和 Unicode 规范化冲突。

## 4. 性能基准

使用公开生成的无敏感数据 Vault，记录硬件和版本：

- 1 万、5 万和 10 万小文件；
- 1 GiB 和 10 GiB 混合附件；
- 单个大文件及中断续传；
- 无变化扫描、少量变化和首次全量同步；
- Windows Docker bind mount 与客户端移动设备内存峰值。

0.3 的最低目标是：无变化同步不读取文件正文；传输内存上限与 Chunk 并发数相关，而不是与文件总大小相关。具体耗时阈值在获得基准机器数据后固定。

## 5. 平台人工矩阵

| 平台 | 1.0 要求 |
|---|---|
| Windows 桌面 | 必测；Docker Desktop 服务端和至少两个客户端场景 |
| macOS 桌面 | 兼容验收；大小写和路径语义重点测试 |
| Android | 至少一台真机；后台恢复、网络切换和内存限制 |
| iOS/iPadOS | 至少一台真机或明确记录暂未覆盖；Capacitor Adapter 行为 |

每次稳定发布至少验证首次同步、普通修改、附件、删除、冲突、离线恢复、插件文件同步和重启提示。

## 6. 发布门禁

- `go test ./...`、`go vet ./...`；
- 插件 typecheck、bundle、单元测试和状态机测试；
- Docker 镜像构建、健康检查和持久化冒烟测试；
- 数据库从所有受支持历史版本升级；
- 备份恢复演练；
- 依赖、代码、镜像和 secret 扫描；
- Release 元数据、校验和、SBOM 和构建来源验证；
- Beta 至少经过规定灰度期，不能直接从开发版本提升为 Stable。
