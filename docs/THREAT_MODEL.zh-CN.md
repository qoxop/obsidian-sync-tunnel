# Sync Tunnel 威胁模型

## 1. 适用范围

本文描述 1.0 可信自托管模式。1.0 不是零知识系统：同步文件、路径和历史版本在服务器磁盘、SQLite 及备份中均可能以明文存在。

## 2. 需要保护的资产

- Vault 文件内容、文件名、目录结构和历史版本；
- 可选的本地 Admin Token、每设备凭据、一次性配对码和 Cloudflare Access Secret；
- 设备身份、Vault 标识和操作审计；
- SQLite、Chunk 存储、日志和备份；
- 插件发布包、服务端源码构建和升级链路。

## 3. 信任边界

### 可信

- 用户控制的 Obsidian 设备；
- 用户控制的 Windows 主机、Docker Desktop 和宿主机文件系统；
- 用户明确选择的加密备份目标。

### 有条件信任

- Cloudflare Tunnel 和 Access：负责传输入口与边缘认证，但不作为数据端到端加密边界；
- GitHub Releases 和 BRAT：只负责分发插件，必须通过校验和、插件 SBOM 和不可移动 Tag 降低供应链风险；服务端由用户从同名 Tag 源码本地构建；
- 其他 Obsidian 插件：可能在自己的 `data.json` 保存敏感内容，完整同步模式会复制这些数据。

### 不可信

- 公共互联网；
- 未注册或已撤销设备；
- 未经授权访问宿主机 `/data`、备份或 Token 文件的本地账户；
- 任意来自请求参数的路径、ID、哈希和元数据。

## 4. 主要威胁与缓解

| 威胁 | 1.0 缓解措施 | 剩余风险 |
|---|---|---|
| 互联网扫描和撞库 | Tunnel、Access Service Token、每设备高熵凭据、限速 | Cloudflare 或凭据配置错误仍可能暴露入口 |
| 凭据泄露 | SecretStorage、服务端哈希、可选只读 Admin secret、scope、轮换和撤销 | 已获得设备凭据的攻击者在撤销前可访问对应 Vault |
| 宿主机磁盘被读取 | Windows ACL、BitLocker、最小容器权限、加密异机备份 | 服务器在线且主机被攻破时明文可见 |
| 路径穿越 | 服务端规范化、拒绝绝对路径和 `..`、不跟随外部符号链接 | 平台路径语义差异仍需客户端预检 |
| 恶意大文件或请求洪泛 | 配额、单请求限制、Chunk 限制、并发和速率限制 | 自托管主机资源有限，仍可能暂时不可用 |
| 重放或网络重试 | TLS、operation ID、base revision、事务幂等 | 合法设备被完全控制时无法区分恶意操作 |
| 静默覆盖或删除传播 | 乐观锁、冲突副本、首次预览、tombstone、版本恢复 | 用户主动确认错误计划仍可能造成广泛变更 |
| 数据库或 Chunk 损坏 | WAL、哈希校验、doctor、在线备份和恢复演练 | 同机无备份时硬盘损坏仍会造成数据丢失 |
| 日志泄密 | 禁止记录 Token、Secret、文件正文和完整路径；诊断脱敏 | 错误堆栈和第三方组件仍需审查 |
| 供应链攻击 | 锁文件、CodeQL、依赖扫描、插件 checksum/SBOM、不可移动 Tag，以及从同名 Tag 本地构建服务端 | GitHub 账户被接管或用户使用第三方镜像仍是高影响事件 |
| 其他插件秘密被同步 | 默认安全模式、敏感路径警告和完整模式确认 | 无法可靠识别所有第三方插件秘密格式 |

## 5. 安全默认值

- 宿主机端口只发布到 `127.0.0.1`；
- 管理端点使用独立 localhost 监听、回环 Host 与同源 Origin 校验，不进入公共 Tunnel；多人共用主机可启用 Token；
- Cloudflare Access 作为推荐的第二层认证；
- 默认不同步 Sync Tunnel 自身目录、工作区状态、缓存、日志和临时文件；
- 设备凭据不进入插件 `data.json`；启用时 Admin Token 不进入 Compose 环境变量、镜像层或 Git；
- 不启用客户端遥测；
- 备份不包含 Token，并明确标记其中含有明文 Vault 数据；
- 新设备首次接入只生成预览，不立即传播删除。

## 6. 不在 1.0 内解决的风险

- 管理员、宿主机恶意软件或被盗备份读取 Vault 明文；
- 流量观察者从请求时序和大小推断活动；
- 已解锁 Obsidian 设备上的本地恶意软件读取笔记；
- 恶意社区插件读取 Vault 或 SecretStorage；
- 多用户之间的服务端隔离和不可信管理员。

这些风险中的服务器明文问题由 2.0 E2EE 处理；终端被攻破和恶意插件不属于 E2EE 可以完全解决的范围。

## 7. 安全发布门槛

- 所有鉴权、路径、配额和幂等逻辑有自动测试；
- 支持 Token 和设备撤销并在集成测试中验证；
- 公开发布前启用 GitHub Private Vulnerability Reporting；
- 插件 Release 提供 SHA-256 和 CycloneDX SBOM；服务端不发布预构建容器，部署者从同名 Tag 本地构建；
- 完成一次从异机备份恢复到全新数据目录的演练；
- 安全文档明确披露网络访问、外部服务、明文存储和完整同步的秘密复制风险。
